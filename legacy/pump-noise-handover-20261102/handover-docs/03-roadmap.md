## 二、P0 · 先做能防事故的（发布与数据层面）

### P0-1 发布事实卡自动化 ◐

现状：check:apk 已能输出 build 号、包 SHA-256、内容指纹、证书 SHA-256；文档 02 已给出模板。但还没有脚本把 JSON 自动写进发布说明或版本记录。

剩余工作：

1. 新增 `scripts/release-card.mjs`：读 check:apk JSON，生成一段固定格式文本，落盘到 `.apkwork/releases/buildN.json`。
2. 在打包流程最后一步自动调用，失败则阻断发布。

验收：同一张事实卡能唯一对应一个 APK 文件；把 APK 重新打包但内容不变时，contentSha256 一致、整包 SHA 允许因签名时间不同而不同。

### P0-2 安装策略与数据保全 ◐

现状：同证书可覆盖升级这一事实已写进交接文档；未提供基线导出/导入。

剩余工作：

1. 增加「导出全部数据」：settings、presets、baseline、crest history、background、license，打包为 JSON 文件。
2. 增加「导入数据」：校验 schema 版本，冲突时给出覆盖/合并选项。
3. 升级前提示：检测到旧版本数据时，先导出再升级（可选）。
4. 明确卸载/换机/清缓存三种场景的恢复路径。

验收：升级一次不丢基线；卸载后通过导出文件能恢复 100% 关键数据；导入错误文件不破坏现有数据。

### P0-3 真机六项回归 ○

必须逐项在真机执行，并留录屏或截图：

1. 48 kHz 正常采集。
2. 44.1 kHz 设备：应走重采样并标 invalid「采样率非 48k，阶次结论不可用」。
3. 削顶：连续 3 点 ≥0.95 判 clip，结论变 invalid。
4. Worklet 掉帧：人为制造卡顿，应提示掉帧并降级。
5. 麦克风被系统切走：mic lost 后停止分析并提示。
6. AGC 开启：检测到自动增益后标 agc，结论不可信。
7. 额外：移动端授权页与许可证输入流程。

验收：每条有设备型号、系统版本、操作步骤、预期、实际、截图/录屏、结论。缺一项不能宣称「真机验证完成」。

### P0-4 轴频不确定度现场标定 ◐

现状：算法已输出 ±95% 不确定度，报告已打印；尚未用已知转速泵做现场标定。

剩余工作：

1. 选一台铭牌明确、工况稳定的泵（优先 46 Hz 场景）。
2. 在同一测点采 3 组、每组 ≥60 s，记录 trackedF0、σ、窗数、梳强度。
3. 与铭牌对比，确认 σ ≤ 0.3 Hz（46 Hz 下约 0.65%）。
4. 把结果写进基线说明与报告样例。

验收：至少一台设备、一个测点归档 `shaftHz ± σ`；偏差结论能复现。

### P0-5 门限冻结闭环 ◐

现状：event-rail 支持手动冻结、冻结后随基线版本固化、运行期只读；历史 ≥200 帧才允许冻结；未冻结时只记录不报警。缺三项定义：

1. 用户始终不点冻结时的长期行为（是否永远只记录）。
2. 冻结后能否解冻/重建。
3. 重建基线是否自动重算门限。

建议状态机：未就绪 → 可冻结 → 已冻结 → 重建中 → 已冻结。规则：

- 历史 ≥200 帧且基线就绪 → 可冻结，界面常驻提示。
- 可冻结状态持续 14 天仍未操作 → 每次启动弹一次强提示，并写入事件轨。
- 解冻需二次确认；解冻后回到可冻结，历史保留。
- 重建基线时，默认不自动覆盖已冻结门限；提供「随新基线重算」复选项。

验收：自动提示、手动冻结、重建三条路径都有可复现步骤与截图。

## 五、建议新增（交接时发现，原路线图未覆盖）

### N-1 git 基线 ○

当前目录不是 git 仓库，只有 .github_repo 记录远端。没有提交历史，任何「哪个包对应哪次改动」都无法回答。

做法：

```bash
cd <项目根目录>
git init
git add -A
git commit -m "baseline: Build 4 / v1.3 handover snapshot"
git remote add origin <远端地址>
```

注意：提交前确认 .gitignore 已排除 node_modules、.env、.vercel、.apkwork。license/private.pem 绝对不要提交。

### N-2 数据迁移与备份 ○

所有关键数据在 localStorage，清缓存/换机即丢。除 P0-2 的导出/导入外，建议：

1. 自动备份：每次建立新基线时，把上一版基线存为 `baseline-backup`，保留最近 2 份。
2. 版本迁移：存储 key 已带 v1/v2，新增字段时必须写迁移函数，不允许直接改 key 版本了事。

### N-3 完全离线 ○

index.html 引用了外网 extensions.js。离线时不影响使用，但会产生控制台错误，且未来平台脚本变更可能引入不确定性。建议打包时移除该标签，或在 WebView 拦截并返回空脚本。

### N-4 基线/门限的现场可解释性 ○

报告里已有数值，但现场人员不一定理解「crest z」「梳强度」「工况档」。建议增加一页「名词解释 + 本次判读怎么读」，降低误读。

## 七、全局完成定义

一个版本可以发布，必须同时满足：

1. typecheck 零错误，音频测试全绿。
2. build 成功，8081 首屏无 JS 错误（或有明确豁免记录）。
3. check:apk ok=true，事实卡四元组齐全。
4. 同证书覆盖升级验证通过，数据不丢。
5. 真机六项回归有记录；未做的项必须在发布说明里列出。
6. 路线图状态更新，未完成项有下一版归属。

## 八、当前最大风险（按影响排序）

1. 基线只存 localStorage，卸载或换机即清零，且没有导出/导入。
2. 没有 git 历史，出问题无法回滚到「上一版可工作的代码」。
3. 真机回归缺失，44.1 kHz/削顶/AGC 这些会让结论 invalid 的场景没有现场证据。
4. 门限冻结没有长期提醒，可能长期「只记录不报警」而无人发现。
5. 授权私钥与代码同目录，分发源码时极易泄露。
