# 05 · 现有资产迁移与落地代价

> 结论先行：**能复用的是“声学证据层”，不能复用的是“监护产品层”。**
> 最短路径 = 保留 DSP + 测试 + APK 壳，砍掉在线监护与 SSR/账号/授权门禁这两块旧债，先把“一次现场会话”跑通。

## 0. 结论先行

1. **可直接复用三块**：① `src/lib/audio/*` 纯函数 DSP + 30 条 golden/优先级测试；② WebView APK 壳 + NativeBridge + 扫码；③ `report.ts` 的字段模型 + PNG/CSV/JSON 导出。它们已经过 Build 4 验证，改动成本最低。[F]
2. **必须重做两块**：① 产品壳与信息架构（设备列表/24h 漂移/告警中心 → 现场会话七步）；② 持久化（localStorage → IndexedDB + 案例库 + 导出/导入）。这两块与旧定位绑定，改皮无意义。[F/I]
3. **必须砍掉两块旧债**：① 24h 在线监护/推送/沉默期/健康分；② TanStack Start SSR + better-auth + PGLite + 强制授权门禁。它们让离线现场变重、让安装变脆、让包体不可追溯。[F/I]
4. **必须先补四个前置条件**（否则现场闭环不成立）：资产/测点几何模型、会话状态机、报告 manifest/哈希、真机六项回归。旧路线图的 P0 大部分要保留，但语义从“监测可用”改为“诊断可复现”。[F]
5. **重做代价**：从 Build 4 到“听诊仪 MVP（规则版，无双麦方向/无模型）”约 **39–52 人日**；到“完整（含双麦+端侧模型+交接+复测）”约 **88–122 人日**；含样本放行 100–145 人日（不含真实故障样本采集标注）。[I]
6. **决策 D1/D3/D4 的增量**：双麦探测/标定/方向 8–11、端侧模型 5–8、片段与留存 2–3、覆盖升级 1–2，合计 16–24 人日；已并入 88–122。[I]
7. **最大的隐性成本不是代码，是数据**：基线导出/导入、真机回归、轴频现场标定、13 号样本放行，这四项不做，功能越多越危险。[F]

### 5.1 关键路径上最容易被低估的三项

1. **真机回归**（5–8 人日只是修复，不含设备采购/借测）：44.1k、削顶、AGC、mic 切走会直接改变三态，必须在现场机型上跑。
2. **旧数据迁移**（包含在 6–9 人日）：localStorage 的基线/事件历史没有 schema 版本化；必须先导出再迁移，不能“直接换 key”。
3. **报告哈希/证据链**（包含在 5–7 人日）：PNG data URI、原始帧、算法版本、基线版本、门限值必须一次打通；否则报告不可复核。

## 6. 迁移顺序（最快跑通现场闭环）

### 阶段 0：先让仓库可信（3–5 天）

1. `git init`，当前 Build 4 作为 baseline commit；`.gitignore` 排除 `node_modules/.vercel/.apkwork/license/private.pem`。
2. 音频测试独立跑通：`golden.test.ts` + `status-priority.test.ts`。
3. 把 `check:apk` 接进打包；先不改产品。
4. 导出旧 localStorage 六类数据为 JSON（只读工具，不动现有 App）。

### 阶段 1：MVP 现场闭环（约 25–35 天）

**顺序**：DSP 抽取 → 三态/有效性 → 会话状态机 → 测点/采集/证据页 → 报告 2.0 → IndexedDB → 真机回归。

**验收**：一台泵、一个测点、一次 15 分钟内完成；报告含 8 项元数据；断网可用；升级不丢数据；六种 invalid 都能复现。

### 阶段 2：Agent + 复测 + 交接（约 15–25 天）

**顺序**：工具契约 → 编排/拒答 → 复测对比 → 交接包 → 提示词/离线模板。

**验收**：50 条脚本化会话无禁止输出；证据不足必拒答；同点复测 Δ≤1.5dB 才可比；接班人凭交接包复现。

### 阶段 2.5：双麦 + 端侧模型（决策新增，约 16–24 天）

**顺序**：`stereo.probe` 探测矩阵（4 机型）→ 通道映射 → 90s 拍手标定 → GCC-PHAT 粗方向 → 单麦降级 UI → 模型运行时 + 3s 超时 + 数值校验 + 模板回退。

**验收**：GT31–GT41；不支持机型全部落到单麦且 UI 明示；模型未装/超时/幻觉数字三条路径都回退模板；报告 `versions` 完整。

### 阶段 3：样本放行与规模化（约 15–25 天）

**顺序**：13 号协议 → 标注/盲测 → 逐类放行（仅汽蚀、堵塞）→ 覆盖升级演练。

**验收**：每类过 C31；未过类仍只输出“疑似/需复测”；Build 4→v2.0.0 覆盖安装保数据。
