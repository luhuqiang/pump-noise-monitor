## 0. 结论先行

1. 旧项目的**物理约束**是对的：单麦零空间自由度、绝对 SPL 不可测、稳态声只能做统计异常检测、故障名需要真实标注放行、长积分换频率分辨率、crest/kurtosis 门限不能随劣化漂移。这六条全部继承，不推翻。[F]
2. 旧项目的**产品范式**是错的：它把自己做成“常驻在线监护仪表”，而现场工程师的任务是“到点、对准、采集、判定、留证、交接”。范式必须换，DSP 与判据可以留。[F/I]
3. 15/16 号评审推翻了 09 号界面规格中的三处旧口径：`confidence<0.7→unknown`、`SNR≥25dB` 单阈值、`削顶率>5%` 单判据。新口径是**三态 + 双 SNR 阈值 + 连续 3 样点平顶**。[F]
4. 16 号评审进一步把“44.1kHz 直接 fail-closed”改为“重启 ≤3 次后接受 44.1k、内部重采样、标 invalid、禁用阶次”。这是**可用性与物理诚实**的折中，采纳 16，不采纳 12 的硬失败。[F]
5. 08/09 的设计语言可继承约六成：浅色为默认、深色仅手动反转（07 §2.1）、状态色语义、信号健康条、证据卡、事件轨独立、低置信不显示数字、48px 触控。必须重做的是：设备列表首屏、24h 漂移热力图、告警中心/推送/沉默期、“这不是异常”自动调阈值。[F/I]
6. 13 号样本方案给出的放行门槛必须写进 Agent PRD：任一类故障名要 recall≥0.80、precision≥0.85、macro-F1≥0.80、unknown 召回≥0.90、跨设备下降≤10pp、相邻强度混淆≤25%、每类≥100 段真实样本 + 双人复核。未达标的类，只能输出“疑似/需复测”。[F]
7. 所有数字型约束已收敛为 **C01–C42 物理约束台账**（§5），作为 03/06 的硬输入；任何实现不得绕过，改判据必须同时升 `algorithm_version`。[F/I]

## 4. 08/09 设计资产：继承、改造、重做

### 4.1 可直接搬（保留视觉与交互语义）

| 资产 | 处理 | 理由 |
|-|-|-|
| 深色工业底色 `#0E1116/#141922/#1A2030` | **仅作为深色手动主题，不作默认** | 泵房/机房弱光、强光下高对比；现场长时间看屏不刺眼 |
| 状态色只表达状态（绿/黄/红/灰） | **直接搬** | 现场一眼判读；禁止装饰性用色 |
| 等宽数字 + 12px 最小字号 | **直接搬** | 频率/转速/σ 需要对齐扫读；户外可读 |
| 信号健康条（AGC/削顶/SNR/权限/采样率） | **直接搬并前置** | 现场第一信任物件；从“设置页”提到采集页常驻 |
| 证据卡：基线 vs 当前叠加 + 偏离高亮 | **直接搬** | 用户能自己判断是否误报；报告核心图 |
| 事件轨独立一行（计数+近期频次） | **直接搬** | 与趋势分离，避免“一个数解释所有故障” |
| 低置信不显示数字，只显示色带/“数据不足” | **直接搬** | 物理诚实；现场避免锚定 |
| 空态给下一步操作 | **直接搬** | 现场新人可用 |
| 触控 ≥48px、戴手套可点 | **直接搬** | 现场约束 |
| 200ms 淡入、无横向滑动、无装饰动效 | **直接搬** | 工业场景低动效 |
| 告警卡“结论一句 + 证据一句 + 建议一句” | **改造** | 现场改为“本次结论 + 关键证据 + 下一动作”，≤80 字 |
| 基线向导五步（放置/工况/采集/确认/验证） | **改造** | 扩为现场七步；保留“拍照存档 + 工况绑定 + 质量门 + 用户确认 + 复核测量” |

### 4.2 必须改造（语义从“监护”换到“诊断”）

| 旧资产 | 改造为 | 理由 |
|-|-|-|
| 设备列表首屏 | **今日任务/测点首屏**：待测、待复测、待交接 | 工程师是“来干活”，不是“来看仪表” |
| 单设备详情（24h 漂移） | **本次会话证据页 + 历史复测对比** | 现场没有 24h 连续数据；比较对象是“同点同工况的上一次” |
| 告警中心/推送/沉默期 | **案例收件箱/待复核清单** | 无后台常驻，推送模型不成立；交接靠清单 |
| `normal/attention/alert` 设备状态 | **`ok/low_confidence/invalid` 本次判读态 + 关注级别** | 三态是数据可信度，不是设备健康度；两者不能混 |
| “这不是异常”自动 +5% 阈值 | **“标记为误报/待复核”只记录** | 无标注自动调阈值会污染判据；违反 16 号原则 |
| 5 分钟基线 + 自动更新 | **验收基线/出厂基线 + 显式重建** | 现场首次巡检常常没有 5 分钟；自动更新会吸收劣化 |
| 实时轮询/WebSocket | **本地会话，无网络依赖** | 泵房网络差；离线优先 |
| 频谱热力图 24h | **测点×工况×时间的复测矩阵（只存会话）** | 数据量小、可解释 |
| “设备在线/离线” | **资产是否建档/测点是否标定** | 现场没有在线概念 |

### 4.3 必须重做（旧范式直接删除）

- 常驻后台监听、自动告警、推送、沉默期。
- 以“异常分 0–1”作为首屏主视觉。
- 以波形作为首屏（稳态波形正常/故障几乎无差异）。
- 任何“预测性维护/剩余寿命”暗示。
- 任何绝对 dB SPL 数值或“声压级”单位。
- 任何单麦“定位到轴承/叶片”的交互暗示。

## 6. 由参考资产得到的三条“不可协商”产品判断

1. **产品形态不是“监测”，是“受控实验”**：现场诊断的物理本质是“固定一个变量、改变另一个变量、看差异”。Agent 的核心职责是选择下一次测量，不是选择形容词。[I]
2. **“测不了”必须是一等公民**：三态与拒答不是兜底，而是产品的核心交互。能把“测不了”说清楚，才配说“测到了”。[F]
3. **报告是交付物，屏幕不是**：现场工作的闭环在“接班人能复现”。没有版本、几何、哈希、原始帧的报告，等于没有报告。[F]
