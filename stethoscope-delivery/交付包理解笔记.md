## 0. 这份交付包是什么

**一句话：这是一个"开工前"的设计与需求总包，不是可运行的产品，也不是 APK 发布包。**

它把旧"泵噪监测台"项目的物理约束、失败教训和现有代码盘点，收敛成一套自洽的现场诊断产品定义：**Android WebView + 手机自带麦克风 + 48kHz 真值 + 纯本地离线 + 只承诺汽蚀/堵塞两类故障名 + 原始音频默认不留**。包内真正"可运行"的只有两个东西：单文件交互原型 `prototype/index.html`，以及旧工程快照 `legacy/pump-noise-handover-20261102.zip`（只作对照）。

**解决什么问题**：把"常驻在线监护仪表台"改成"到点即测、证据化判读、可复核交接"的现场工具。核心不是报警，而是**在测不准时明确说测不准**（三态 `ok / low_confidence / invalid`）。

**面向谁**：现场巡检/设备工程师（戴手套、强光、单手、泵房弱网/无网），以及接手的开发 Agent/研发团队。README 明确把阅读顺序定为"先 06，再 07"。

**交付边界**：
- 端：Android 为主，界面基准 390×844；无云端、无账号、无在线监护。
- 声学：单麦为主，第二颗麦"探测通过才用"；禁止源分离、方位/距离定位、RUL、绝对 dB SPL。
- 结论：只放行"汽蚀""堵塞"两个故障名，且必须过逐类样本放行门槛；其余一律"疑似/需复测"。
- 数据：原始音频默认不留；只留特征、片段（默认关）与元数据。
- 发布：沿用 `com.luhuqiang.pumpnoise` 与原证书，versionCode 4→5 覆盖升级。

可以这样记依赖关系：

- **00 / 01 是"上游法源"**：所有数字型约束（采样率、窗长、SNR 双阈值、基线 30 帧/3 档、crest 冻结 200 帧等）都在 `00` §5 的 C01–C42，任何实现不得绕过。

- **03 是"Agent 行为契约"**：T01–T16 工具的输入/输出/失败语义、`ok/low_confidence/invalid` 放行条件、会话状态机、`EvidenceBundle` / `AgentDecision` / `ReportManifest` 的 JSON Schema。
- **04 是"措辞层"**：P0–P6 提示词只能把结构化证据转成现场话术，禁止生成数值、故障名、SPL。
- **05 是"旧资产账本"**：明确哪三块直接复用（`src/lib/audio/*`、WebView 壳+NativeBridge+扫码、`report.ts` 字段/导出），哪两块旧债必须砍（24h 在线监护；TanStack SSR + better-auth + PGlite + 强制授权门禁）。
- **06 是"施工图"**：把 02/03 落成 M00–M11 模块、16 个 store、错误码、性能预算、45 条 Golden Test、打包签名流程。
- **07 是"验收面"**：浅色纸感 token、P0–P8 页面状态矩阵、AC-01–AC-24 可判定条目；原型与它"CSS 变量同名同值"。

### 2.2 原型：唯一能"看见产品"的东西

`prototype/index.html` 是单文件、零外链、可离线打开的合成数据原型：

- 覆盖 P0 引导（4 步，localStorage 记忆）、P1 idle 仪表台、P2 采集中、P3/P4/P5 三态结果、P6 设置、P7 模块 sheet、P8 测点 sheet。
- 仪表台模块：波形、频谱（25 带）、阶次、趋势、事件轨、质量灯；最多同时 3 个，选择持久化。
- 交互细节按 07 实现：长按 800ms 结束采集、30s 上限、`prefers-reduced-motion`、浅色默认、深色仅手动。
- 验收钩子：`?t=guide|idle|capture|result|sheet|settings&s=ok|low|bad&theme=dark&mods=wave,spec`。
- **它是演示，不是采集器**：波形是 canvas 画的模拟线，不申请麦克风、不做 FFT；三态靠 `?s=` 或底部"原型演示"按钮切换。

因此，原型能验收"布局、状态表达、交互手感"，不能验收任何声学结论。

## 3. 核心逻辑与业务链路

### 3.1 现场会话七步（02 §3）

准备 → 认机/建档 → 测点 → 采集 → 判读 → 复测 → 报告 → 归档/交接

关键门：

| 步 | 通过门 | 产物 |
|---|---|---|
| 认机 | 资产唯一、关键参数（转速/叶片/极数）齐 | `asset_id` |
| 测点 | 距离/高度/朝向/照片齐全，背景可辨 | `point_id` + `geometry_hash` + `placement_fp` |
| 采集 | 三态 ok、阶次可用（rpm≥900 且 ≥20 转） | 原始块 + 特征 |
| 判读 | 无禁止输出；机制假设 + 证据 + 反证 + 验证实验 | 判读卡 |
| 复测 | 回访首点 Δ≤1.5dB，几何/工况可比 | 对比卡 |
| 报告 | 8 项元数据齐全（几何、工况、基线版本、算法版本、采样率真值、麦位、哈希等） | PDF/MD/JSON/PNG + manifest |
| 交接 | 字段完整、权限允许 | `.tzcase` 交接包 |

时间预算：首次巡检 12–15min，复测 5–6min，应急初筛 2–3min；超时优先砍"多点扫描"，不砍质量门。

### 3.2 Agent 分层与三条不变量（02 §4）

感知层（采集/质量/上下文）→ 证据层（谱/阶次/包络/事件/基线/多点）→ 推理层（确定性门控 + 机制融合 + 措辞）→ 交互层（一次一个动作、三态、拒答）。记忆层存案例/基线/机队。

不变量：

1. **工具优先**：任何数值只能来自工具输出，LLM 不得计算/外推。
2. **门控优先**：`validity`/`orders`/`baseline` 的 invalid 优先于任何机制分。
3. **证据可追溯**：每个结论字段能指回 `session_id + tool + params + version`。

### 3.3 端侧处理管线（06 §3–§4 + 03 §5）

```
M00 壳/构建
  └ M01 采集前端（AudioRecord/Worklet、48k、PCM16 单通道、掉帧）
      ├ M02 双麦探测/通道映射/标定/GCC-PHAT 粗方向（失败即 mono_fallback）
      └ M03 有效性（采样率真值、44.1k 重采样、削顶 3 点、AGC 1.8dB/8s、掉帧、静音、非稳态）
            └ M04 证据引擎（FFT/1-3oct/轴频阶次/包络/事件轨）
                  ├ M05 基线与复测（20 维指纹、马氏距离、冻结门限、90d/500h 老化）
                  └ M07 Agent 编排（工具调度、门控、三态、拒答、状态机）  ← M08 模型（可选）
                        └ M09 报告/片段/导出
                              └ M06 资产/测点/案例/交接（与 M10 存储、M11 许可交叉）
```

关键参数（均来自 C01–C42，不是"建议值"）：

- 趋势窗 32768 点 @48k = 0.6827s，Δf=1.4648Hz，Hann ENBW≈2.20Hz；快窗 8192 点；事件帧 4096 点≈85.33ms。
- 判据用 Z 计权（不计权）；A 计权只显示；A 在 46Hz 约 −32dB。
- 异常分 = 20 维马氏距离 d → `score=100(1−e^(−d/2.2))`；**不是概率**，关注 60/告警 80。
- 滞回按时间：升 2s / 降 3.4s；`unknown` 进 1.2s / 出 3s。
- 双 SNR：质量展示 ok≥24/25dB，判据门≥10dB。
- 冻结门限：历史 ≥200 帧才可冻结，`crestGateZ=median+1.4826MAD`。

输入输出契约：工具输出 `EvidenceBundle`（每项带 `tool_version/params_hash/algorithm_version`），Agent 输出 `AgentDecision`（三态 + 机制 + 下一动作 + 限制），报告输出 `ReportManifest`（8 项元数据 + 哈希 + 版本）。

### 3.4 存储与迁移（06 §5）

DB `ausculto`，16 个 store：`meta/sites/assets/points/sessions/captures/evidence/baselines/gates/events/cases/reports/handovers/clips/settings/migrations`。旧 localStorage 只读迁移，缺几何的旧基线标 `unverified`，不参与趋势/复测；迁移失败回滚到备份。

### 3.5 双麦与端侧模型（条件能力，不是卖点）

- 双麦：探测独立通道 → 标定 → GCC-PHAT 粗方向；相干<0.6、峰突出<6dB、σ_τ>0.5 sample 任缺即 `unknown`；两路复制/副路削顶/副路 AGC 都退回单麦并明示。禁止跨通道比幅、禁止用双麦推 SPL。
- 模型：≤300MB GGUF（0.5B 级）、内存 ≤600MB、上下文 1024、首 token ≤2s、总超时 3s；**不随 APK 打包**，缺模型走模板；输出要过"数值一致性 + 禁止词 + 三态一致"校验，任一失败丢弃。

### 3.6 涉及"听诊仪硬件"的部分

本产品没有专用硬件，所谓"听诊仪"是**手机 + 自带麦 + 壳**：

- 麦克风：优先非 `communication` 类型的底部主麦；探测第二颗麦是否独立；48kHz 真值；AGC/NS/AEC 视为不可逆污染。
- 壳：Android WebView + NativeBridge（麦克风权限、文件导出/分享、扫码）；06 M00/M11。
- 发布：`apktool` 重打包 + `zipalign` + `apksigner` v2/v3；沿用旧证书；versionCode 只增不减；覆盖安装要演练且不得丢基线。

### 3.7 怎么运行

- **原型**：浏览器直接打开 `prototype/index.html`，或本地静态服务；无网络依赖。
- **旧工程**：Node 22/24 + `npm ci` → `npm run dev`（8080）；`npm run test` 覆盖 `golden.test.ts`、`status-priority.test.ts` 等；`npm run build` 在旧架构下是 SSR 产物（`.vercel/output/static` 无 `index.html`），06 要求改成静态 Vite 直接出 `index.html`。
- **APK**：`06` §13.2 给出静态化后的打包流程，但 `apktool.jar` 不在本包，需要按 `GET-APKTOOL.txt` 自行获取。

## 7. 风险点（仅提示，未改动任何文件）

**信息暴露 / 去敏不彻底**

- `docs/00_参考资产与冲突裁决.md` §1.2/§1.3 保留了 14 篇飞书文档的 URL + token、7 篇工程交底的 token，以及作者邮箱；`04`/`06`/`07` 也含作者邮箱。对外转发需二次去敏。
- legacy `README-HANDOVER.txt` 含 **APK SHA-256 与证书 SHA-256**，zip 内还保留 `META-INF/PUMP.RSA`/`PUMP.SF`（证书本体）。这与 `00` §1.3 声称"本批产出不含证书指纹/APK 哈希"不一致——虽非私钥，但属于可关联指纹。
- `FEISHU-EDITION.txt` 含完整包本地路径与整包 SHA-256，暴露内部工作区路径。

**硬编码路径 / 环境耦合**

- legacy `startup-workspace.sh` 写死 `/workspace/pump-noise-monitor`。
- legacy README 明确提示 `apkwork/tools` 路径"需按本地实际位置改写"；06 §13.2 的命令也是相对路径假设。
- legacy 无 `.git`，但保留 `.gitignore`、`.github_repo`、`AGENTS.md`、`vercel.json`，容易误判为"可直接接着开发"。

**缺失依赖 / 平台不兼容**

- `apktool.jar` 缺失（FEISHU 版为压 20MB 移除），且 `aapt2`、`zipalign`、`lib64/*.so` 是 Linux/ELF 工具，Windows 下不能直接执行；需 WSL 或 Android SDK build-tools。
- 密钥包不在本包，`handover-docs/04-secrets.md` 也不在 legacy；任何"签名/授权"步骤当前都不可复现。
- 旧工具链依赖 JDK 17 / Node 22+ / unzip，README 有写，但本机是否具备未验证。

**重复 / 废弃 / 噪声文件**

- `design/` 同时保留 3 个概念方案与最终方案，易误用（`icon_final.svg` 才是唯一几何依据）。
- legacy `app/.grok/skills` 有 **81 个与本产品无关的 skill 文件**，另有 `preview.pid`、`preview.log`、`screenshots/`、`artifacts/imagine_images/` 等运行垃圾。
- legacy `apkwork/monitor/assets/www/__grok/` 里仍是 **Grok 品牌安装页**（`logo-grok.svg`、两张 ~100KB onboarding 图、`manifest.webmanifest`），旧 APK 壳带着第三方品牌资源，存在品牌/合规与包体问题。
- `apkwork/monitor/build/apk/` 是旧构建中间物（`classes.dex`、`resources.arsc`、`resources.zip`）；`assets/www/assets/index-C4kuLIni.js`(422KB)、`routes-D05SbWLX.js`(407KB) 是**打包产物**，不是源码，不能当实现参考。
- `app/src/lib/` 仍保留 better-auth、PGlite、pg、jose、`license-gate.tsx`、`license.ts`、`multiplayer/p2p.ts` 等旧债；直接沿用会与"纯本地、无账号、无云"冲突，也与当前授权 App 的路线纠缠。

**产品/合规风险（文档自身已标）**

- 绝对 SPL、未放行故障名、定位、RUL、源分离都是拒答项；实现时任何"提升/显著/智能"措辞若无成对实验支撑都应删除。
- 45 条 GT 未跑意味着"验收标准存在，但产品未被验证"；U01–U10 未关闭意味着关键阈值仍是假设。
- "双麦"不能写进宣传前提；第二颗麦只是条件能力。
